## 設計メモ

- **通信は FakeNet に差し替える。** 同一プロセス内の共有ストアなので、ホストとゲストを同時に動かして
  実際のやり取りを再現できる。`net.js` の `LocalBusNet` は BroadcastChannel が要るので Node では使えない。
- **`G` は script.js の実ファイルから抽出して使う** (`harness.js` の `extractG`)。
  テスト用に手書きすると本体と乖離し、テストが通るのに本番で落ちる状態になるため。
- **script.js 全体は読み込まない。** DOM 依存が重く、対象は netgame.js の通信層なので
  ゲームエンジン側 (`cpuDiscard` / `renderAll` など) はスタブにしてある。
- 切断は `store.simulateDisconnect(uid)` で再現する (予約された `onDisconnect` を発火させる)。

## 検証できないこと

以下は Node テストの範囲外なので、リリース前に実ブラウザで確認すること。

- **描画** — 山・王牌・河が正しい位置に出るか (特に山データを wall パスへ分離した v0.9.7 は要確認)
- **Firebase の rules** — `?local=1` は Firebase を経由しないため、ルールの誤りを検出できない。
  ルール変更後は必ず本番URLで1局通す
- 実機のタッチ操作 (ドラッグ打牌)、PWA / Service Worker のキャッシュ更新
